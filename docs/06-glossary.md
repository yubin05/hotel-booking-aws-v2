# 06. 용어 정리

문서에 나오는 용어를 쉬운 말로 풉니다.

## 장애 대비

| 용어 | 뜻 |
|---|---|
| RTO | 장애가 난 뒤 서비스가 다시 돌아가기까지 걸리는 시간 |
| RPO | 장애 때 잃어도 되는 데이터의 시간 범위. 예: 마지막 백업 이후 15분 |
| HA (고가용성) | 서버나 AZ 하나가 고장 나도 서비스가 계속되게 하는 것. 예: Multi-AZ |
| DR (재해 복구) | 리전처럼 큰 단위가 멈췄을 때 다른 곳에서 서비스를 되살리는 것 |
| AZ | 리전 안의 독립된 데이터센터 묶음. 서울 리전에는 AZ가 여러 개 있다 |
| Multi-AZ | 서버나 DB를 AZ 두 곳 이상에 나눠 두는 구성 |
| Backup & Restore | 평소에는 백업만 두고, 장애 때 인프라를 만들고 복원하는 DR 전략. 가장 싸고 가장 느리다 |
| Pilot Light | 다른 리전에 DB만 켜서 복제해 두고, 장애 때 서버를 켜는 전략. 가스레인지의 불씨에 비유한다 |
| Warm Standby | 다른 리전에 전체를 작게 켜 두고, 장애 때 키우는 전략 |
| Active-Active | 두 곳 이상이 모두 실제 트래픽을 처리하는 전략. 가장 빠르고 가장 비싸다 |
| PITR (시점 복구) | 백업과 변경 기록으로 원하는 시각의 상태로 DB를 되돌리는 것 |
| Failback | 장애 때 옮겨 간 서비스를 원래 위치로 되돌리는 것 |
| 스플릿 브레인 | 두 곳이 동시에 쓰기를 받아 데이터가 갈라지는 상태. 이를 막으려고 한쪽 쓰기를 차단하는 것을 펜싱이라고 한다 |

## 앱 구조

| 용어 | 뜻 |
|---|---|
| 모놀리스 | 앱 전체를 하나로 배포하는 구조 |
| 마이크로서비스 | 기능별로 서비스를 나눠 따로 배포하는 구조 |
| 분산 모놀리스 | 서비스를 나눴지만 서로 동기 호출로 묶여 따로 살 수 없는 구조. 나눈 비용만 들고 이점은 없다 |
| 모듈러 모놀리스 | 하나로 배포하되 코드 안에서 기능별 모듈 경계를 지키는 구조 |
| 멱등성 | 같은 요청을 여러 번 보내도 결과가 한 번 보낸 것과 같은 성질. 예: 결제 버튼을 두 번 눌러도 예약은 1건 |
| 12-Factor | 설정을 코드와 분리하고 환경 변수로 받는 등 클라우드에 올리기 쉬운 앱을 만드는 원칙 모음 |

## 데이터 이관

| 용어 | 뜻 |
|---|---|
| 덤프 | 특정 시점의 DB를 SQL 파일로 통째로 떠내는 것. 한 번 찍는 사진이라 이후 변경은 따라가지 않는다 |
| 복제 (소스–레플리카) | 원본 DB의 변경 기록을 다른 DB가 계속 받아 따라 적용하는 것. 실시간 중계에 가깝다 |
| CDC | 변경분만 계속 잡아서 옮기는 방식 (Change Data Capture) |
| DMS | AWS의 DB 이관 서비스. 처음에 전체를 복사하고(Full Load) 이후 변경분을 따라간다(CDC) |

## 배포와 운영

| 용어 | 뜻 |
|---|---|
| CI/CD | 코드를 합칠 때마다 자동으로 테스트하고(CI) 운영 환경에 배포하는 것(CD) |
| 롤링 배포 | 서버를 조금씩 새 버전으로 바꿔 가는 배포 방식 |
| Blue/Green | 새 버전 환경을 통째로 따로 띄운 뒤 트래픽을 한 번에 옮기는 배포 방식 |
| Circuit breaker (ECS 배포) | 새 버전이 계속 실패하면 배포를 멈추고 이전 버전으로 자동 롤백하는 기능 |
| OIDC (GitHub → AWS) | 액세스 키를 저장하지 않고, GitHub가 발급한 임시 신분증으로 AWS 권한을 받는 방식 |
| walking skeleton | 코드→빌드→배포 경로를 처음부터 끝까지 먼저 연결하고, 기능을 나중에 붙이는 진행 방식 |
| DORA 지표 | 데브옵스 성과를 재는 지표. 배포 빈도, 변경 리드타임, 변경 실패율, 복구 시간 |
| ADR | 설계 결정 기록. 무엇을 왜 골랐고 무엇을 버렸는지 남기는 문서 |

## AWS 구성 요소

| 용어 | 뜻 |
|---|---|
| CloudFront VPC Origin | 인터넷에 노출되지 않은 내부 ALB를 CloudFront의 원본으로 쓰게 해 주는 기능 |
| Internal ALB | 사설망 안에서만 접근할 수 있는 로드밸런서 |
| NAT Gateway | 사설망의 서버가 인터넷으로 나갈 수만 있게 해 주는 출구. 밖에서는 들어올 수 없다 |
| WAF 요청 수 기반 규칙 | 같은 곳에서 일정 시간에 너무 많은 요청이 오면 차단하는 규칙 |
| 데이터 플레인 / 컨트롤 플레인 | 실제 요청을 처리하는 부분 / 설정을 바꾸는 부분. 장애 중에는 설정 변경(컨트롤 플레인)에 의존하지 않는 설계가 더 안전하다 |
