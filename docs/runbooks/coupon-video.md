# 쿠폰 이벤트 포트폴리오 영상 촬영 런북

> 75초 편집본용. 집 PC · OBS 1080p/30fps. **촬영용 회차는 성능 검증 회차와 다른 조건**이다.
> 3,000명이 같은 T에 경쟁한 실험 결과는 [실험 기록](../experiments/migration.md)에서 확정된 회차만 인용한다. 아래 촬영은 2,999 k6 손님 + 실제 손님 1명, 실제 손님을 위해 1장을 먼저 확보한 뒤 T에 2,999명이 누른다. 3,000명 동시 실험이라고 소개하지 않는다.

## 1. 촬영 전에 (T = k6 발급 요청 시각, KST)

- [ ] 성능 검증 회차 10 결과 · [ADR-080](../04-decisions.md#adr-080) 확인. 실패/503/쿠폰 대기 p95/조회 p95는 원본 확인 후만 결과 카드에 기입. 회차 10이 통과하지 않으면 구성 재확인.
- [ ] 집 PC 시간 동기화, 테스트 계정 및 메일함 준비, 결제 **테스트** 환경/테스트 카드 확인. 테스트 계정은 본인 또는 테스트용 메일 주소(공개용 가명) 사용. 다른 실제 손님의 접근이 없는 촬영용 환경에서 실시.
- [ ] `bash scripts/preflight.sh` · `aws login` · `aws login --profile admin` · `eval "$(ssh-agent -s)"; ssh-add ~/.ssh/hotel-legacy`. 관리자 역할 세션은 2시간, 끝 검증/시간 분석/로그 수집 시 다시 확인.
- [ ] `node load/grafana/coupon-dashboard.mjs` → Grafana Cloud에서 [전체 JSON](../../load/grafana/coupon-dashboard.json) 기존 UID `cloudlab-coupon` 갱신 및 [촬영 JSON](../../load/grafana/coupon-video-dashboard.json) 별도 Import(UID `cloudlab-coupon-video`). 기존 대시보드 내보내기를 백업. Prometheus(k6) · CloudWatch 데이터 소스 연결. 새 회차 `testid`와 시간 구간을 확인. 원본 공개 공유 링크/권한 변경 금지. 1초 전송 · 5초 화면 갱신(서비스 제한에 따라 더 느릴 수 있음), ECS/ALB 1분 데이터는 지연 가능. 데이터 없음은 0건이 아님.
- [ ] OBS A: 좌측 사이트 시크릿 창(60%) + 시계, 우측 촬영용 Grafana(40%). B: 메일 창 + 같은 Grafana. C: 전체 화면 실측 결과 카드(후편집). 쿠폰 발급/쏠림 사이에는 멈추지 말고 스파이크 전후를 연속 녹화한다.

## 2. 인프라 올리기 (T보다 충분히 일찍)

`infra/seoul/terraform.tfvars`에 아래 **촬영 조건**을 넣는다. 기존 줄을 중복 추가하거나 다른 기존 사용자 설정을 덮어쓰지 않는다.

```hcl
multi_az = true
db_pool_size = [5, 1]
coupon_service = true
coupon_tasks = 4
alb_access_logs = true
```

모듈의 쿠폰 DB 연결 기본값은 `[4, 3]` (회차 10 구성, `infra/modules/regional/variables.tf`). 일반 서비스 최대 4 × 6 + 쿠폰 4 × 7 = 연결 52(설계값). 회차 10의 결과 확인 후 이 구성을 채택할지 결정한다. 기존 요청 수 목표 추적 관련 설정도 회차 10과 동일하게 유지.

`infra/seoul/main.tf`의 로컬 `scale_events`에 **당일 KST 실제 T**로 예약 추가(예시 T 20:00, 날짜 교체). 현재 Seoul 루트는 이 값을 tfvars가 아니라 main.tf에서 지정한다. 날짜가 있는 로컬 실험 예약은 커밋하지 않는다.

```hcl
scale_events = [
  { name = "coupon-video", start = "YYYY-MM-DDT19:55:00", end = "YYYY-MM-DDT20:10:00", min = 2, max = 4 },
]
```

```bash
bash scripts/up.sh load
```

- 이미 서울이 떠 있다면 서울 `terraform plan` → 적용 범위 확인 → `terraform apply` 및 필요시 CD; 적용할 때 쿠폰 대상 그룹/서버/규칙은 Terraform의 의존 순서를 따른다.
- 일반 서버 app과 쿠폰 서버 coupon(4개) 모두 최신 이미지, ALB 정상 대상, Valkey 번호표, 앱과 쿠폰의 1초 지표를 확인. 서비스/토스/메일은 테스트 계정으로 스모크 검증. 발생기는 검증 회차의 크기 사용(예: t3.xlarge).
- 관리자/SSH 연결, Grafana 전송 설정(`~/.hotel-legacy/grafana.env`, 값을 화면/로그에 노출하지 않음), 날짜·시간대 확인.
- 새 대시보드 미반영 상태라면 실제 촬영 전에 Import/서울 apply 확인. 코드 변경만으로 Grafana Cloud가 자동 갱신되지는 않는다.

## 3. 촬영 회차 (T 최소 30분 전 시작, 2026-11-27 사용자 요청으로 변경)

T = k6 손님 2,999명이 쿠폰을 누르는 시각. 쿠폰 이름은 **"깜짝 할인 이벤트"**, 실제 손님용으로 **T-1분에 먼저 열린다**(예: 손님 1:00, k6 1:01). 가입(비밀번호 해시라 2,999명 약 21분)은 **T-6분까지 화면 밖에서 끝내고**, **T-5분 ~ T-2분에 손님이 몰려와 T까지 10초쯤마다 숙소를 둘러본다** → 관제 화면에 요청 · 일반 서버 수(자동 확장, 이벤트 최대 4)가 늘어나는 장면. 손님 선발급은 스크립트가 공개 쿠폰 목록의 남은 수로 자동 확인(터미널 입력 없음, 못 받아도 회차는 계속하고 `video-demo.txt`에 기록). 결과 폴더 · testid는 `coupon-video-*`로 분리, 일반 회차 동작은 그대로.

```bash
# T를 당일 실제 시각으로 교체. 백그라운드로 돌려도 됨(터미널을 볼 필요 없음)
VIDEO_DEMO=1 CLAIMERS=2999 COUPONS=100 bash load/run-coupon.sh 01:20 scheduled
```

`scale_events`는 T-8분 ~ T+15분, min 2 · max 4(손님이 몰려오기 전부터 이벤트 구성).

| 실제 시각 | 손님 · 운영자 행동 |
|---|---|
| T-30분 이전 | 실행. 2,999명 가입이 화면 밖에서 진행. 브라우저 계정 미리 로그인. |
| T-6분 | OBS 연속 녹화 시작(관제 화면이 아직 조용한 장면) |
| **T-5분 ~ T-2분** | 손님 2,999명이 몰려와 숙소 둘러보기 → 요청 · 서버 수 증가 |
| **T-1분** | "깜짝 할인 이벤트" 쿠폰 받기 → 받자마자 숙소 → 객실 → 쿠폰 적용 예약 시작 |
| **T** | k6 2,999명 동시 발급 요청(99장, 나머지 소진). 손님은 결제 진행. 시계/그래프로 쏠림을 함께 녹화. |
| T~+4분 | 숙소 → 객실 → 쿠폰 적용 → 토스 테스트 결제 → 예약 완료 → 메일. 메일이 늦으면 녹화 계속, 조회 부하 종료(T+4분경) 이후임을 표시. |
| T+10분 이후 | 종료 예약 실행/일반 최대 8 복귀 확인. 검증 기록과 원본을 비공개 보관. |

k6 발급 기대값은 99장, 소진 정상 응답 기대값 2,900건(2,999−99), SQL 전체 발급 수/사용자 수는 100이다. **기대값이지 실측 결과가 아니다.** 실패하면 녹화본을 성공 회차로 쓰지 않는다. 
`load/results/coupon-video-scheduled-*/`의 `video-demo.txt`, `k6.txt`, JSON.gz, `verify.txt`와 손님 예약/결제/메일 확인. 일반 회차의 결과표에는 합치지 않는다. `video-aborted.txt`가 있는 회차는 제외.

## 4. 개인정보 체크 및 영상 편집(75초)

- [ ] 서비스 로그인: 이메일/아이디, 개인 이름, 전화·예약자 연락처, 비밀번호/자동완성/브라우저 계정 프로필. 개발자 도구는 닫고 HAR, Authorization, 세션 쿠키, API 키/결제 키, 토큰을 영상에 노출하지 않는다.
- [ ] 결제: 테스트 카드만, 카드번호·유효기간·CVC·거래 식별값·결제 상세 개인 정보 마스킹. 예약 번호 및 바코드·QR에 개인 식별/접근 정보가 있으면 가림.
- [ ] Gmail: 계정 주소/프로필·다른 메일·연락처·메시지 ID·예약자 개인정보 가림. 제목(예약 확정)·수신 시각·예약 완료 상태만 식별 가능하게.
- [ ] Grafana/콘솔: 개인 이메일/계정 ID·권한 정보·토큰·내부 접속 주소·터미널 로그인 정보 가림. 불필요한 창, 알림, 비밀 파일은 녹화 전 닫기. 블러 후 프레임 이동·화면 전환 구간도 재확인.

| 편집 시간 | 영상 · 자막 |
|---|---|
| 0–5초 | 타이틀·아키텍처: 대규모 쿠폰 쏠림 대응 검증 |
| 5–15초 | 손님이 몰려오며 요청 · 서버 수 증가, 로그인 · "깜짝 할인 이벤트" 1장 받기(촬영 조건 표시) |
| 15–25초 | 실제 k6 요청 집중, 일반 숙소 조회. 발급은 T보다 앞선 구간임을 유지; 실시간 그래프가 늦으면 같은 회차의 시간 일치 기록과 구분 표기 |
| 25–45초 | 쿠폰 적용 예약 → 토스 테스트 결제·완료 |
| 45–55초 | 예약 확정 메일 수신 |
| 55–75초 | 독립 3,000명/100장 실측 회차의 식별자·HTTP 503·예상 밖 응답·대기 p95·조회 p95·SQL 발급 확인(실측 숫자). 쿠폰 전용 서버 분리 + Valkey 번호표 |

**편집 원칙:** 쏠림/응답 시간 구간은 1배속(불필요한 대기만 컷), 영상에 나온 회차와 결과 카드의 회차를 명시, 실제 관측하지 않은 메트릭/그래프를 합성하지 않음. 쿠폰 소진 409는 정상 거절로 별도 표기. 실측 원본은 편집 전 보관.
