## 조건과 한계 (실행 전에 적음)

- **HTTP.** 3단계는 HTTPS(CloudFront)라 암호화 연결 비용이 더해진다. 1단계 HTTP에서 예약 화면이 멈춘 사례처럼 조건 차이가 동작을 바꿀 수 있다([03 결과 기록](../03-plan.md#결과-기록)).
- **가입 계정 50개를 손님들이 나눠 씀.** 3,000개를 만들면 가입(느린 비밀번호 해시)에 몇 분이 걸려 시험 전에 앱 CPU를 쓰고, 계정 목록이 손님마다 복사돼 발생기 메모리가 커진다. 회원이 많은 DB는 seed-volume의 회원 2만 명으로 갖춤(로그인은 안 되는 회원).
- **발생기 1대 = 출발지 IP 1개.** 실제 사용자는 IP가 많다. 3단계 WAF 요청 수 제한은 IP 기준이라 같은 방식이면 발생기가 차단될 수 있다 → 3단계 설계 때 확인.
- **인터넷 지연 없음.** 같은 서울 리전이라 발생기 → 앱 4.4ms(내 PC → 앱 14.4ms, 각 1회). 측정값은 서버가 일한 시간에 가깝다.
- **t3 크레딧 unlimited.** 크레딧 제한 없이 잰다(IDC 서버 · Fargate와 같은 조건).
- **회차 사이 DB · 앱은 그대로.** 예약이 회차마다 수백 건 쌓이지만 지난 예약 10만 건에 비하면 작다.
- **숙소 이미지 · 화면 파일(HTML · JS)은 요청하지 않음**(E-01과 같음).
- **발생기가 병목이면 그 회차는 무효.** 발생기 CPU 80% 이상 또는 메모리 90% 이상(k6 권장선).
